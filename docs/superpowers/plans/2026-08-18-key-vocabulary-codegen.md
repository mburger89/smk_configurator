# Key Vocabulary Codegen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate the entire key vocabulary for both repos from one `keycodes.json` manifest, and add the 83 missing HID keyboard-page keycodes.

**Architecture:** A JSON manifest in `~/esp/SMK` is the single source of truth. `generate_keycodes.sh` emits `KeyCodesGenerated.swift` into both repos — the firmware gets `KeyCode` + `fromCString`, the configurator gets `KeyName` + `displayLabel` + palette group arrays. Tasks 1–2 introduce the generator with **zero vocabulary change** so the machinery is proven against today's behavior before Task 3 adds any keys.

**Tech Stack:** Swift 6 / Embedded Swift (firmware), SwiftCrossUI (editor), Swift Testing in both, `python3`-in-bash generator, CMake (6 firmware build files), SwiftPM.

**Spec:** `docs/superpowers/specs/2026-08-18-key-vocabulary-codegen-design.md`

## Global Constraints

- **Two repos.** Firmware `~/esp/SMK`, editor `~/esp/smk_configurator`. Every regeneration commits outputs in **both**.
- **Editor build/test:** `swift build --target SMKConfigurator --build-system native`, `swift test --build-system native`. Never a bare `swift build` — it compiles swift-cross-ui's Windows-only backend and fails.
- **Firmware host tests:** `SMK_HOST_TESTS_ONLY=1 swift test` from `~/esp/SMK`. This is the **only** firmware verification available on this machine — no embedded target can be built or flashed here. Every firmware claim must be either host-tested or explicitly labelled unverified.
- **Token naming:** camelCase full words (`keypadAsterisk`, `international1`). Matches existing `leftBracket` / `printScreen`.
- **Generated files carry** `// Generated by generate_keycodes.sh from keycodes.json.` / `// Do not edit by hand -- edit the JSON and re-run the script.` and are never hand-edited.
- **Generator must be deterministic:** same manifest ⇒ byte-identical output. Preserve manifest order; no dict iteration, no timestamps.
- **`SMK_KEYMAP_MAX_LEN` (4085) is not changed.**
- **Payload cap:** 4085 bytes for the layers array.
- Commit after each task. Editor repo auto-commits per its CLAUDE.md convention.

## Deviations from the spec (read before starting)

**1. Generated `if`/`strcmp` chain, not a table-driven lookup.** Spec §3.1 specified `static let table: [(StaticString, KeyCode)]`. Two problems found while planning:

- A global `static let` array of tuples in **Embedded Swift** needs runtime lazy initialization, and neither the embedded build nor a flashed board can be verified from this machine (Global Constraints). Introducing that risk in a file that compiles flat into six embedded targets is not worth it.
- The table's only benefit was reducing hand-maintained boilerplate — and once the chain is *generated*, its length costs nothing to maintain. Codegen already solves the drift problem the table was reaching for.

So the generator emits the same `if strcmp(...) == 0 { return .x }` shape the firmware uses today, just generated. Behavior is provably identical to current code, which is exactly what Tasks 1–2 verify.

**2. Manifest carries `token` and `name` separately, and the two repos' Swift case names are unified.** The digits are the reason: firmware spells them `case k1` (matching `strcmp(cStr, "1")`), the editor spells them `case n1 = "1"`. Same wire token, different Swift identifiers. The manifest therefore holds `token` (wire string) and `name` (Swift case, **identical in both repos**), and the editor's `n1…n0` become `k1…k0`.

Rename surface verified as near-zero: firmware tests reference only `KeyCode.a`; editor code reaches `KeyName` through `KeyName(rawValue:)`, `.allCases`, and the group arrays — all of which are generated or name-agnostic.

- [ ] **Step 4: Write `generate_keycodes.sh`**

```bash
#!/usr/bin/env bash
# Regenerates the key vocabulary for both repos from keycodes.json. Run after
# changing that file; commit the outputs in both repos.
#
#   ./generate_keycodes.sh [path-to-smk_configurator]   (default ../smk_configurator)
set -euo pipefail
cd "$(dirname "$0")"
CONFIGURATOR="${1:-../smk_configurator}"

python3 - "$CONFIGURATOR" <<'PY'
import json, pathlib, sys

configurator = pathlib.Path(sys.argv[1]).expanduser()
manifest = json.load(open("keycodes.json"))
keyboard = manifest["keyboard"]

BANNER = ["// Generated by generate_keycodes.sh from keycodes.json.",
          "// Do not edit by hand -- edit the JSON and re-run the script.",
          ""]

def swift_string(s: str) -> str:
    return s.replace("\\", "\\\\").replace('"', '\\"')

# --- firmware: Sources/SMKCore/KeyCodesGenerated.swift ---------------------
f = list(BANNER)
f += ["// Host-only: strcmp comes from the bridging header (newlib) on embedded",
      "// builds; the host SMKCore build needs it imported explicitly.",
      "#if canImport(Darwin)", "import Darwin",
      "#elseif canImport(Glibc)", "import Glibc", "#endif", "",
      "// Keycodes based on HID standards.",
      "enum KeyCode: UInt8 {",
      "    case noKey"]
for e in keyboard:
    f.append(f"    case {e['name']}")
f += ["    case transparent // Like QMK's KC_TRNS",
      "",
      "    // Explicit rawValue overriding the synthesized ordinals: these are real",
      "    // HID usage IDs, which is what HIDReport.addKey puts on the wire. Note",
      "    // the synthesized init?(rawValue:) is therefore inconsistent (it maps",
      "    // from ordinals) and must stay unused -- see the design doc's Risks.",
      "    var rawValue: UInt8 {",
      "        switch self {",
      "        case .noKey: return 0x00"]
for e in keyboard:
    f.append(f"        case .{e['name']}: return 0x{e['usage']:02X}")
f += ["        case .transparent: return 0xFF",
      "        }",
      "    }",
      "",
      "    // Generated if-chain rather than a table: a global array-of-tuples needs",
      "    // runtime lazy init under Embedded Swift, and this file compiles flat",
      "    // into six embedded targets that cannot be built or flashed from a dev",
      "    // machine here. Generated length costs nothing to maintain.",
      "    static func fromCString(_ cStr: UnsafePointer<Int8>) -> KeyCode {"]
for e in keyboard:
    f.append(f'        if strcmp(cStr, "{swift_string(e["token"])}") == 0 {{ return .{e["name"]} }}')
f += ["        return .noKey", "    }", "}", ""]
pathlib.Path("Sources/SMKCore/KeyCodesGenerated.swift").write_text("\n".join(f))

print("wrote Sources/SMKCore/KeyCodesGenerated.swift")
PY
```

```swift
import Foundation
import Testing
@testable import SMKConfigurator

/// The cross-repo agreement check that did not exist before this suite. KeyName
/// here and KeyCode in ~/esp/SMK are generated from one manifest; if they drift,
/// this app writes tokens the firmware parses as .noKey and the key silently
/// does nothing on a real keyboard.
@Suite("Key vocabulary agrees with the firmware manifest")
struct KeyVocabularyTests {

    /// Reads ~/esp/SMK/keycodes.json. Skips (rather than fails) when the
    /// firmware repo is not checked out beside this one, so CI on a runner
    /// with only this repo stays green.
    static func manifest() throws -> [[String: Any]]? {
        let url = URL(fileURLWithPath: NSHomeDirectory())
            .appendingPathComponent("esp/SMK/keycodes.json")
        guard FileManager.default.fileExists(atPath: url.path) else { return nil }
        let obj = try JSONSerialization.jsonObject(with: Data(contentsOf: url))
        return (obj as? [String: Any])?["keyboard"] as? [[String: Any]]
    }

    @Test("every KeyName case appears in the firmware manifest with the same usage")
    func namesMatchManifest() throws {
        guard let entries = try Self.manifest() else { return }
        let byToken = Dictionary(uniqueKeysWithValues: entries.compactMap { e -> (String, [String: Any])? in
            guard let t = e["token"] as? String else { return nil }
            return (t, e)
        })
        for name in KeyName.allCases {
            guard let entry = byToken[name.rawValue] else {
                Issue.record("KeyName.\(name) has no manifest entry")
                continue
            }
            // The check that matters: not just that both sides know the token, but
            // that they agree on which HID keycode it means.
            #expect(entry["usage"] as? Int == Int(name.hidUsage),
                    "KeyName.\(name) is usage \(name.hidUsage) here, "
                    + "\(entry["usage"] as? Int ?? -1) in the manifest")
        }
        #expect(KeyName.allCases.count == entries.count)
    }

    @Test("usage values are pinned to the HID table")
    func usagesArePinned() throws {
        guard let entries = try Self.manifest() else { return }
        let usage = Dictionary(uniqueKeysWithValues: entries.compactMap { e -> (String, Int)? in
            guard let t = e["token"] as? String, let u = e["usage"] as? Int else { return nil }
            return (t, u)
        })
        #expect(usage["a"] == 0x04)
        #expect(usage["1"] == 0x1E)
        #expect(usage["backslash"] == 0x31)
        #expect(usage["semicolon"] == 0x33)
        #expect(usage["application"] == 0x65)
    }

    @Test("every KeyName is reachable from exactly one palette group")
    func everyKeyIsInExactlyOneGroup() {
        let grouped = KeyName.allGroups.flatMap(\.keys)
        for name in KeyName.allCases {
            #expect(grouped.filter { $0 == name }.count == 1,
                    "KeyName.\(name) is not in exactly one palette group")
        }
    }
}
```
